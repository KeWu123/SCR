# Correct native alternatives and concurrency protocol

Specified before execution, 2026-10-16. Native dependencies are (NumPy 1.26.4, PyArrow 21.0.0, LanceDB 0.40.0), with SQLite supplied by Python. The broker implementation is imported and its hash recorded.

The primary scale grid is (N=2,000,d=32), (N=10,000,d=64), with seeds 11,29,47. Add (N=50,000,d=64), all three seeds, if practical. Uniform Float32 vectors, independent queries, replacements from a seeded permutation plus Gaussian noise. An initial committed SQLite history/source cut 0 has N keys at version 1. A native LanceDB IVF_HNSW_FLAT table contains exactly those row/version/vector records; four partitions, M=16, construction ef=64. All arms search the identical native generation with nprobes=4, ef=128, 40 candidates, output limit 10, and the same source/version/payload check. This is a modest CPU reference implementation, not a production scale or approximate-search throughput claim.

Three correct alternatives:

1. **Episode serialization lock:** a shared/exclusive gate admits concurrent readers, holds its shared side for the entire episode, and gates the complete writer source/index publication under its exclusive side. Admission checks the current source cut and retains an independent native checkout. It allows only the current coherent pair. Source and index cannot advance while any episode remains open.
2. **Retained generation wrapper:** a small registry admits source cut 0 atomically with a retained native generation. Each episode establishes a real SQLite WAL read transaction and retains its independent native checkout for its lifetime. Publication provides a checked immutable source/version/payload map. New source/index versions may publish while episodes retain the old pair. Support withdrawal and in-flight query references delay reclamation. For a single exact source cut this is algorithmically equivalent to SCR's support/pin protocol; no extra incompatibility is imposed on the wrapper.
3. **SCR lifecycle broker:** the current `NativeBroker`, including its existing full source/index population validation, source frontier checks, private native checkout on admission and on each query, and pins/withdrawal/GC. A fresh checkout per query is a reference implementation choice; the wrapper is permitted to retain its checkout and is not slowed to match it.

Full publication includes an atomic committed source scan, native open/checkout, native population/vector scan, duplicate and coverage checks, and creation of an immutable source/payload view plus population keys. One warmup then three measured publications per arm. Common source materialization and native indexed build are timed separately. Query timing is 48 warmups then 240 measured operations per arm, interleaved in rotating arm order; each sample includes native search, candidate transfer, row/version filtering and payload association. Record separate 240 begin/end samples and three full 16-query episodes, each including begin, all queries and end. The long-lived query benchmark excludes publication/admission; the full episode numbers include admission/close. p99 always reports its sample count and is an exploratory statistic, not a well-resolved tail guarantee.

Concurrency uses physical copies of the same committed initial SQLite file and indexed LanceDB directory. For each primary cell/arm, run genuine 100 and 300 ms requested holds with 1 and 4 simultaneous reader episodes. Queries execute continuously in real threads until the requested deadline; release waits for in-flight queries, so measured holds may exceed the request. A real writer atomically appends 25% replacements plus 10% deletes (half reinserted at version 3) to SQLite cut 1, then deletes/adds corresponding native records and validates the new native/source publication. The serialization gate covers all this writer work. Retained/SCR episodes remain on cut 0. Record actual writer attempt/acquire/source-commit/publication/end timestamps; whether source commit and complete publication precede reader release; gate wait; writer full latency; every concurrent query latency and answer mismatch. No modeled or simulated wall time. Native writer work preserves the initial index plus newly unindexed fragments; no retraining is hidden in the writer cost. Query workloads remain on the identical initial fully indexed generation.

Source database/WAL/SHM files, all native data/index/manifest files, logical history row counts and serialized/Python metadata sizes are captured before, while old episodes remain retained, and after withdrawal/release/reclamation. Every measurement reports its scope. SQLite storage includes its WAL/SHM and the broker owner lock separately. Native file lists and sizes are recorded. Source anchors are pruned only after release, and physical native cleanup then runs. Metadata size is an explicit Python/JSON reference representation, not a lower bound for optimized implementations. Concurrency copies may be removed after saving file inventories; initial databases and inputs remain available for independent native population inspection.

Correctness evidence includes exact equality of all arms' answers, version/payload soundness, recall against a separate scalar Float64-distance oracle for the first 16 queries, complete native population/vector identity, initial indexed query plans, immutable old answers during genuine writer progress, and deterministic paused-query/end/GC and admission/withdrawal races. The independent verifier imports no experiment implementation or broker code; it reconstructs source updates, reads initial native population, computes scalar distances independently, recomputes metrics/timestamp predicates and checks hashes. Artifact hashes bind protocol, driver, implementation and input files.
