Locked before execution. A source SQLite history table retains row/version/vector/payload/tombstone records by source commit; source epoch1 changes are atomic. Native LanceDB manifests have checked-out versions and exact source-version population/embedding validation. The broker implements actual Begin/Query/Withdraw/End/GC on those native objects, not a separate model.

Reject publishing current native data as source0; accept correctly matched current/source1. Query old token after maintenance. GC while old support open; admit a new source0 token after GC. Withdraw future source0; reject new0 admission while existing0 continues. Use threads to pause Begin before registration while withdrawal/GC attempts proceed; registry lock must protect native object/history until registration. Release last pins, GC source rows and drop old native handle; cleanup obsolete physical native versions in this isolated database, and require reopening the old native version to fail. New current/source1 reads remain valid after cleanup.

Observe version/payload soundness, native indexed query plan, exact actual candidate/embedding certificate, supporting/unsupported admission outcomes, source row counts/anchor retention, after-maintenance answer consistency and completed physical reclamation. No throughput claim for this full-population publication scan.
