# Snapshot-Consistent Retrieval (SCR)

Code and recorded experiments for **Coverage Is Not Freshness, and Answers Are
Not Realizations: Three Consistency Obligations for Cross-Store Retrieval**.

SCR separates version soundness, population coverage and realization binding
when a transactional source is read together with a mutable vector index.
The reference implementations certify supported source cuts and protect
admitted reads during maintenance and reclamation.

## Setup

Use 64-bit Python 3.12 and install the scientific dependencies in an isolated
environment:

```bash
python -m venv .venv
# Activate .venv using the command for your shell.
python -m pip install -r requirements.txt
python run.py inventory
python run.py verify
```

`verify` checks the finite protocol, retained queue records, support compiler
and retained interval/scaling records. It runs in a temporary copy so the
recorded results stay unchanged. Add `--suite native` to exercise fresh native
broker fixtures. See [REPRODUCE.md](REPRODUCE.md) for all experiments and the
larger saved-evidence checks.

## Code map

| Directory | Contents |
|---|---|
| `reference/` | Strict native version-identity broker and lifecycle regressions |
| `experiments/` | Source/index alignment, measured broker, FIFO queue and finite protocol |
| `experiments/completion/` | Support compiler, native alternatives and reclamation controls |
| `experiments/completion/native_interval/` | Disconnected support, interval admission and history scaling |
| `experiments/head_to_head/` | Native table-version comparison and retained-array accounting |
| `experiments/native_trace/` | FAISS C++ harness, instrumentation patches and compressed raw traces |
| `paper/proto/` | Earlier exact/ANN and PostgreSQL/LanceDB control experiments |
| `paper/exp/` | Graph-placement, navigation and copy-on-write array experiments |
| `paper/audit_20261010/` | Independent checks and corrected earlier diagnostics |
| `completion/measurement_sources/` | Historical measurement drivers for the original exact diagnostic |

The measured broker in `experiments/live_broker.py` and the strict reference in
`reference/native_broker_strict.py` have different source identities. The
recorded timings belong to the measured implementation. The strict reference
adds canonical key validation and failure-atomic publication; its performance
is not inferred from those timings.

Recorded query answers, input arrays and timings are included. Native runtime
databases and compiled libraries are regenerated by the experiment drivers.
Physical database checks require those regenerated databases and fail when
they are absent. A saved verification record does not represent a fresh run.

Machine paths in released metadata have been replaced with relative paths or
neutral labels. [PROVENANCE.json](PROVENANCE.json) separates historical file
hashes from release hashes; recorded source hashes have not been rewritten to
claim that edited release files produced historical measurements.
